# 근로소득 비과세 한도

## 요약

비과세 유형(식대, 자가운전보조금, 보육수당, 연구보조비 등)은 월 한도까지만 비과세이고 넘는 금액은 과세 급여에 더합니다. 회사가 설정에서 한도를 따로 정하면 법정 한도와 작은 쪽을 씁니다. 같은 유형의 여러 항목은 한도를 나눠 씁니다.

## 현행 위치

- 화면: 급여 설정 > 지급 항목의 "비과세 한도 설정", 근로 행의 비과세 열
- 매뉴얼: "비과세 유형은 지정되어 있으며 최대 입력 가능 금액이 제한"
- 재설계 전 구현: `apps/api/legacy/src/modules/payroll/engine/non-taxable.ts`

## 로직

```
법정 월 한도 = 보육수당이면 20만원 × 대상 자녀 수, 아니면 유형의 월 한도
한도 = min(법정 월 한도, 회사 한도)    // 회사 한도가 없으면 법정 한도
비과세 = min(항목 금액, 남은 한도)
과세 = 항목 금액 − 비과세
한도를 넘으면 NON_TAXABLE_LIMIT_EXCEEDED 경고
```

## 서버 이전 시 주의

- 한도는 모두 원문으로 확인했습니다
- 보육수당은 "근로자 또는 그 배우자의 해당 과세기간 개시일을 기준으로 6세 이하(6세가 되는 날과 그 이전 기간을 말한다…)인 자녀의 보육과 관련하여 사용자로부터 지급받는 급여로서 해당 자녀 1명당 월 20만원 이내의 금액"입니다(소득세법 제12조제3호머목2)). 법률 제21221호(2025. 12. 23. 개정, 2026. 1. 1. 시행)가 "월 20만원"을 "해당 자녀 1명당 월 20만원"으로 바꿨고, 부칙 제3조로 2026. 1. 1. 이후 지급분부터 씁니다. 그 전(법률 제19933호, 2024. 1. 1. 시행)은 근로자 한 명에 월 20만원이었습니다
- 서버는 대상 자녀 수를 HR 소득세 공제 설정의 `childcareChildrenCount`에서 받아 근로 행 스냅숏(`snapshot.childcareChildren`)에 복사하고, 보육수당 한도를 20만원 × 자녀 수로 잡습니다. 0명이면 보육수당 전액이 과세입니다
- 자녀 수를 모르면(설정에 값이 없거나, 값을 넣기 전에 만든 스냅숏) 1명으로 보고 `CHILDCARE_CHILDREN_UNKNOWN` 경고를 붙입니다. 자녀 수를 받기 전과 같은 한도라 기존 데이터의 계산이 바뀌지 않습니다. 0명으로 보면 이미 비과세로 주던 보육수당이 말없이 과세로 바뀌어 1명을 골랐습니다
- 한도는 직원 한 명의 그달 한도입니다. 근로소득 행은 직원·귀속월마다 하나라(추가 대장에는 근로 행을 넣지 못하고, 같은 귀속월 근로 행은 `WAGE_INCOME_DUPLICATED`로 막음) 행의 한도가 곧 직원의 월 한도이고, 같은 행 안의 여러 보육수당 항목은 한도를 나눠 씁니다
- 맞벌이 부부가 같은 자녀로 각자 회사에서 보육수당을 받으면 각자 한도를 씁니다. 대상 자녀는 공제대상 가족과 따로 세므로 배우자가 기본공제를 받는 자녀도 넣습니다
- 생산직 야간근로수당은 월정액급여 260만원 이하·직전 과세기간 총급여 3,700만원 이하 요건(시행령 제17조제1항)이 있고, 이 판정은 엔진 밖입니다
- 연 한도 유형은 올해 이미 쓴 금액(`annualNonTaxableUsed`)이 필요합니다. 지금은 행 입력이 주지 않으면 0으로 봅니다
- 화면이 한도를 막지 않고 경고만 하는지, 입력을 막는지는 서버가 정하지 않습니다. 서버는 저장하고 경고합니다
