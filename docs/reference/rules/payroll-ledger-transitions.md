# 급여대장 상태 전이

## 요약

급여대장(현행 급여카드)은 입력가능 → 정산 진행(n/3) → 완료로 갑니다. 급여 아웃소싱(BPO)은 담당자가 계산해 고객에게 승인을 요청하고 고객이 승인해야 마감됩니다. 직접 운영(현행 급여관리)은 승인 없이 마감합니다. 원천세가 신고된 지급월의 대장은 금액이 바뀌는 되돌림·반려·승인 취소를 막습니다.

## 현행 위치

- 화면: 급여 정산 목록(`입력가능`, `정산 진행 (n/3)`, `완료`), 상세의 검토 요청·승인·반려·승인 취소 버튼
- 번들: 엔드포인트 `request-approval`, `approve`, `reject`, `cancel-approval`(스펙 3.2). 상태 문자열은 lazy chunk에 있어 없습니다
- 재설계 전 구현: `apps/api/legacy/src/modules/payroll/cards/card-status.ts:14-26`(`CARD_TRANSITIONS`)

## 로직

| 재설계 커맨드 | 전이 | 행위자 | 현행 대응 | 신고 후 |
|---|---|---|---|---|
| `SUBMIT` | 입력 → 제출 | 고객·담당자 | 고객 "검토 요청", legacy 계산 요청 | 막음 |
| `RETURN_TO_DRAFT` | 제출 → 입력 | 담당자(BPO), 둘 다(직접) | 담당자 "해제" | 막음 |
| `REQUEST_APPROVAL` | 제출 → 승인 대기 | 담당자 | `request-approval` | 허용 |
| `WITHDRAW_APPROVAL_REQUEST` | 승인 대기 → 제출 | 담당자 | `cancel-approval`(요청 철회 해석) | 막음 |
| `APPROVE` | 승인 대기 → 마감 | 고객 | `approve` | 허용 |
| `REJECT` | 승인 대기 → 제출 | 고객 | `reject` | 막음 |
| `CLOSE` | 입력·제출 → 마감 | 고객·담당자(직접 운영만) | legacy 담당자 확정 | 허용 |
| `REOPEN` | 마감 → 제출 | 고객·담당자 | `cancel-approval`(승인 취소 해석), legacy 해제 | 막음 |

- 입력은 입력 상태에서 고객·담당자, 제출 상태에서 담당자만 고칩니다
- 명세서 발송·데스크 내보내기는 마감 상태 안의 기록이지 상태가 아닙니다

## 근거

- 스펙 3.2(`docs/reference/spec/payroll.md:285-313`): 상태 머신 제안과 "`cancel-approval`의 주체와 대상 상태는 화면에서 '승인 취소' 버튼이 **승인 완료 대장**에 보인다는 것만 확인했다", "원천세가 신고된 귀속월의 카드에 대한 `cancel-approval`, `reject`, 재계산은 막거나 경고해야 한다(추정)"
- 스펙 3.3(`:315-323`): legacy "`입력가능 → 계산중`: 고객 … `계산중 → 완료`: 담당자가 desk에서 확정 … `계산중|완료 → 입력가능`: 담당자의 '해제'"
- 스펙 6.1(`:728-730`): "원천세 신고 건이 `filed` 이상이면 그 지급월의 대장에 대한 `cancel-approval`, `reject`, 재계산, 추가 카드 생성을 막는다"
- 매뉴얼 `manual/05-급여/02-급여-정산.md:21-49`: 급여 입력 → 검토 요청 → 담당자 계산 → 승인 요청 → 고객 승인 흐름

## 서버 이전 시 주의

- `cancel-approval` 하나를 요청 철회(`WITHDRAW_APPROVAL_REQUEST`)와 마감 해제(`REOPEN`) 두 커맨드로 나눴습니다. 마감 해제는 승인 대기가 아니라 제출로 돌아갑니다
- 반려와 마감 해제는 사유가 필수입니다
- 운영 방식은 대장을 만들 때 회사 설정에서 복사합니다
- 마감 해제는 고객도 할 수 있습니다(현행 고객 "승인 취소" 버튼)
